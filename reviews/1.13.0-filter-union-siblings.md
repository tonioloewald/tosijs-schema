## Findings by severity

### Minor

1. **filter's union-sibling merge only works at the top level. Nested sibling properties are silently dropped** (correctness, **verified**). Location: `src/schema.ts:1208`, `stripSchema`.
   - Repro schema: `{type:'object', properties:{x:{type:'object',properties:{p:{}}}}, anyOf:[{properties:{x:{type:'object',properties:{q:{}}}}}]}`
   - Data: `{x:{p:1,q:2}}`
   - `validate` returns true. `filter` returns `{x:{q:2}}` with no Error, and that result also validates.
   - Cause: `{...rest.properties, ...branch.properties}` lets the branch's `x` replace the outer `x`. The same shallow override applies to `items`.
   - This is not a regression (v1.12.0 gives the same output). But the CHANGELOG line "A key survives if either one declares it" (CHANGELOG.md:27) is false below the first level.
2. **"Both unions apply when both are present" is false: with both anyOf and oneOf, filter returns an Error for data that validate accepts** (correctness; the lens did not verify it, but I reproduced it at HEAD). Location: `src/schema.ts:1129`.
   - Repro schema: `{anyOf:[{properties:{a:{}}}], oneOf:[{properties:{b:{}},required:['b']}]}`
   - Data: `{a:1,b:2}`
   - `validate` returns true. `filter` returns `Error: root: oneOf: matched 0 branches, need exactly 1`.
   - Cause: filterAnyOf strips `b` before filterOneOf runs.
   - Not a regression, but the claim is new in this release and no test covers it.
3. **`src/crossversion.test.ts` leaves a bundle directory in `$TMPDIR` on every `bun test` run** (blast-radius, **verified**). Location: `src/crossversion.test.ts:20`.
   - Lines 20-21 call `mkdtempSync` and `Bun.build({outdir})` at module load, and nothing ever runs `rmSync` or `afterAll`.
   - 37 directories (about 1.7 MB) have built up on this machine. The leak is limited to OS temp space.
4. **The Bun `--outfile` + sourcemap bug is worked around locally but not filed upstream** (blast-radius, unverified). Location: `UPSTREAM.md:35`.
   - The repro is written up and was re-checked on Bun 1.4.2, but no oven-sh/bun issue exists.
   - So the `--outdir` workaround has no exit condition, and sibling repos will hit the same bug.

### Nit

5. **The doc/API sync gate matches export names as whole words in prose** (correctness, unverified). Location: `make-coverage.ts:127`.
   - Names like `s`, `M`, `filter`, `diff` and `validate` are satisfied by ordinary prose, so the gate can stay green after their API docs are removed.
6. **The order of checkExamples findings changed without a note** (correctness, unverified). Location: `src/contract.ts:615`.
   - The walk now visits prefixItems and allOf after anyOf/oneOf.
   - Consumers that snapshot the result array will see a different order.

## Remediation (applied before the tag)

1. **Nested sibling merge:** FIXED. `stripSchema` merges a key both sides declare recursively, through `properties` and object `items`. Tests cover nested properties and items.
2. **anyOf + oneOf:** FIXED. With both present, `anyOf` is treated as a sibling of each `oneOf` branch, and `filterData`'s recursion handles the rest. The repro is now a test.
3. **Temp-dir leak:** FIXED. `afterAll` now runs `rmSync`. 40 leaked directories were removed.
4. **Bun upstream:** handled in this session before the review finished. oven-sh/bun#19729 already tracked it (open since 1.2.12); we commented with the 1.4.2 repro and the `--sourcemap=external` case. UPSTREAM.md links it.
5. **Doc gate prose matches:** FIXED. It now needs code form (`` `name` ``, or `name(`, `name.`, `name<` anywhere). It was seen red when a mention was reduced to prose.
6. **checkExamples finding order:** documented as not part of the contract (JSDoc + CHANGELOG).

Both CHANGELOG claims the review flagged ("either declares it", "both unions apply") are now true and pinned by tests, not narrowed.

## Re-review of the remediation (base 75d792a, always-on, depth=fast)

GO_WITH_FOLLOWUPS, 0 blockers. This is the third round in a row that found edge cases in `filter`'s union stripping, so I stopped patching heuristics and settled each one:
- **CONFIRMED: stricter on invalid input.** With both unions, `filter` errors where 1.12.0 returned data with a declared key silently dropped. The code is kept, because the behavior is more correct and matches `oneOf`-only schemas. Per the repo policy this is breaking, so the release is **1.13.0, not 1.12.1**, with a BREAKING (narrow) CHANGELOG entry, a before/after example, a README upgrade section and a pinning test.
- **Union overwrite in `stripSchema`:** verified, and worse than reported (silent key loss on VALID data). It was fixed with a conservative rule rather than another merge heuristic. Where both sides of a merge carry a union, nothing is stripped at that node and validation decides, so the worst case is a loud Error. Both repros are now tests.
- **crossversion cleanup:** the cleanup is now registered before the build/import.

Because the release became a minor, the pre-minor lenses (efficiency + security) are owed over v1.12.0..HEAD before tagging.

## Fix before the tag (verified majors)

- [ ] **The filter "never returns a forbidden key" claim is broader than the code** (docs, CONTEXT.md:40 and the CHANGELOG headline). CONTEXT.md, shipped as dist/context.md, says flatly "A key an `additionalProperties: false` forbids is never returned." The CHANGELOG bold headline makes the same claim for the case where "no union branch fits". With `skipValidation`, `filter({role:'admin',isAdmin:true}, {type:'object', anyOf:[{properties:{role:{const:'user'}}, additionalProperties:false}]})` still returns `isAdmin`. A bare anyOf of two closed objects also returns `c:3`, though every branch forbids `c`. The README and the CHANGELOG body already say "beside the union"; these two sentences drifted.
  - **Fix:** reword both to "a key that an `additionalProperties: false` *beside the union* forbids". Implementing "drop keys every branch forbids" instead is a scope expansion and would need correctness and blast-radius re-review.
  - **Clears when:** a coverage/contract test pins the stated scope. It asserts the sibling-forbidden key is dropped and documents that a key forbidden only inside a branch is returned under `skipValidation`. Reverting `pruneForbidden` must make the test fail. A docs-only fix needs no re-review beyond Tier 0.

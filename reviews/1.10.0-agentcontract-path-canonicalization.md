## Major (fix before tag, strongly recommended)

### M1 — `normalizePath` canonicalizes only *quoted* brackets; unquoted-bracket and dotted-index respellings still pass the gate ungated

`src/contract.ts:446` — **verified twice** (adversarial pass, and re-reproduced by me at HEAD against `src/`, not the build):

```
gate = agentContract({ 'app.billing': S })     // default unknownPath: 'allow'
  "app.billing.rate"      -> ["app.billing"]   check = Error   (gated)
  "app[\"billing\"].rate" -> ["app.billing"]   check = Error   (gated)
  "app[billing].rate"     -> []                check = true    <-- UNGATED
  "app[\"billing\"]rate"  -> []                check = true    <-- UNGATED

gate = agentContract({ 'app.list[0]': S })
  "app.list[0].rate"      -> ["app.list[0]"]   check = Error   (gated)
  "app.list.0.rate"       -> []                check = true    <-- UNGATED
  "app.list[\"0\"].rate"  -> []                check = true    <-- UNGATED
```

The regex `/\[(["'])(.*?)\1\]/g` requires a quote inside the bracket, so unquoted bodies survive verbatim and dotted indices are never folded to bracket form (or vice versa).

**The dotted-index case is a real gate/applier disagreement in this stack, not a lodash hypothetical.** I ran tosijs's own `/Users/tonioloewald/tosijs/src/by-path.ts`: against `{app:{list:[{rate:1}]}}`, both `app.list[0].rate` and `app.list.0.rate` write to the identical location and both read back through `getByPath('app.list[0].rate')`. The gate recognizes only one spelling. That is verbatim the argument the code's own comment at `src/contract.ts:439-444` uses to justify the leading-bracket fix.

**Additional case not in the original finding:** `app.list["0"].rate` — the release's new normalizer folds a *quoted index* to `.0` while roots keep their `[0]` spelling, so the fold is one-directional. Not a regression (1.9.x also missed it), but it means the new normalizer introduced an index-spelling asymmetry it does not resolve.

**Why not a blocker:** not a regression — 1.9.x failed open on *every* bracket form; `{ unknownPath: 'refuse' }` shipped in this same tag closes it entirely; and `CHANGELOG.md:36` is honestly scoped ("**Quoted-** and leading-bracket paths"). **Why it still matters:** the fail-open is in the DEFAULT mode, and `README.md:496` / `CONTEXT.md:34` tell callers not to hand-roll because a hand-rolled matcher "misses bracket forms" — which over-promises against these spellings. It is one respelling away from the hole this release exists to close.

**Recommended fix** (either, not both):
- (a) Canonicalize *all* bracket segments — `p.replace(/\[("|'|)(.*?)\1\]/g, (_m,_q,k) => '.' + k).replace(/^\./, '')` — which also folds `[0]` → `.0` for roots and paths alike and lets you drop the `startsWith(parent + '[')` arm of `extendsPath`, leaving one canonical grammar. Note this changes root normalization too, so re-check the collision/nesting scan.
- (b) Fail **closed** on what the normalizer cannot canonicalize: after normalizing, if the string still contains `[` or `]`, have `check()` return an `Error` rather than falling through to `affected.length === 0 → true`. This is the posture the module already takes for unenforceable schema keywords.

Extend `src/contract.test.ts:860` ('quoted-bracket paths cannot bypass the gate by respelling') — it enumerates only quoted spellings — with `app[billing].rate`, `app.list.0.rate` and `app.list["0"].rate`.

If M1 is deferred rather than fixed, the *docs* correction is not optional: `README.md:496` and `CONTEXT.md:34` must be narrowed to the CHANGELOG's scope so the shipped surface stops implying total bracket coverage.

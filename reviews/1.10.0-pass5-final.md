## Blocker

### B1 — The shipped account of the `agentContract` matcher gap names the wrong bypass; the real ones are undocumented, and llms.txt contradicts the other five surfaces

**Files:** `README.md:497`, `CHANGELOG.md:60-63`, `CONTEXT.md:34`, `dist/context.md:34`, `src/contract.ts:53-56` (JSDoc → `dist/src/contract.d.ts:44`) and `:446-450` (inline NOTE), `llms.txt:35`. Three of these ship in the tarball (`files: ["dist","CHANGELOG.md","llms.txt"]`).

**Reproduced at HEAD** (real `agentContract`, not the docs' account of it):

```
root `r`:      r.x → ['r']   r[0].x → ['r']   r["x"] → ['r']   r['x'] → ['r']   r.0.x → ['r']
               /r/x → []     ["r"].x → []                          ← undocumented bypasses
root `app.billing`:
               app.billing.rate     → ['app.billing']
               app.billing["rate"]  → ['app.billing']
               app["billing"].rate  → []   check(...) → true      ← the real bypass, undocumented
               /app/billing/rate    → []   check(...) → true
```

Cause is `extendsPath` at `src/contract.ts:442`: `child.startsWith(parent + '.') || child.startsWith(parent + '[')`. Any quoted-bracket or numeric *child* segment keeps the `root[` / `root.` prefix and matches. Only a respelled segment *of the root itself*, a leading bracket, or a different notation escapes.

So five shipped surfaces say `root["x"]` and `root.0.x` "read as uncontracted" — both false — while llms.txt says `affectedRoots` "handles `r.x`, `r[0].x`, `r["x"]`", which is true of that one spelling but is the flat inverse of `CHANGELOG.md:62` and omits the gap entirely. The repo's own test suite refutes its own README twice over: `src/contract.test.ts:809` pins `affectedRoots('billing_rules.0.resource') → ['billing_rules']` (README lists `root.0.x` as unrecognized), and `src/contract.test.ts:950-975` pins the true boundary using `app.billing`. Tests encode the correct behavior; the prose generalizes it wrongly.

**Why this blocks a release whose entire declared payload is "state this boundary honestly and pin it by tests."** The warning is phrased as a falsifiable example and the example is false. A consumer who spot-checks it (`affectedRoots('app["x"]') → ['app']`) rationally concludes the caveat is stale and stays on the default `unknownPath: 'allow'` — while the spellings that do bypass are named nowhere. For an agent reading llms.txt (the LLM-facing doc, least likely to cross-check), the false coverage claim removes the motivation to reach for `{ unknownPath: 'refuse' }`, which is verifiably the correct spelling-independent remedy. `TODO.md:278` files "state the accepted path grammar" as a *remaining* follow-up, so the incorrect text is what ships.

**Fix — docs only, no code, no API change.** Restate once, in the code's own terms, and propagate identically to all six locations:

> A path matches a root when it equals the root or continues it with `.` or `[`. Any spelling of the **subtree** under a root therefore matches (`app.x`, `app[0].x`, `app["x"]`, `app.0.x` all match root `app`). The gap is in the **root's own spelling**: a multi-segment root (`app.billing`) is recognized only when the path spells those segments identically, so `app["billing"].rate` reads as *uncontracted*. A leading bracket (`["app"].x`) and a JSON Pointer (`/app/billing/rate`) also read as uncontracted. If any root has more than one segment, or your applier accepts alternate notations, use `{ unknownPath: 'refuse' }` — it closes every spelling.

Then: add a single-segment assertion to the grammar test (`agentContract({r:S}).affectedRoots('r["x"]') → ['r']`, plus `["r"].x → []`) so the pinned boundary and the prose describe the same thing; regenerate `dist/` so the drift gate stays clean.

**RE-REVIEW SCOPE: Tier 0 only** (doc text + JSDoc + regenerated dist; no runtime code touched), plus one blast-radius re-read of the restated paragraph.

## Run 1 — 2026-08-23 — **BLOCK**

**Verdict: BLOCK** — 1 confirmed correctness regression: `filter()`/`filterData`
over overlapping/subset `oneOf` branches silently dropped a required field on valid
input and reported success — a *new* silent-data-loss path (pre-1.8.0 it errored).

Blocker (fixed pre-tag): for `oneOf:[{a required},{a,b required}]` (both closed),
`validate({a:1,b:2})` is `true` (matches only branch 2), but `filter({a:1,b:2})`
returned `{a:1}` with `isError:false` — it stripped `b` to satisfy branch 1, that
subset self-validated, and the outer `oneOf` re-check passed because only branch 1
now matched. Valid input silently mutated into a lossy object.

Fix: `filterData` for `oneOf` now strips against the branch the ORIGINAL data
matches; when no branch matches as-is, it strips against each branch and keeps the
candidate that RETAINS THE MOST data — never sheds a field a valid interpretation
keeps. A genuine tie returns unstripped so the outer `validate` raises a loud Error.
Regression tests in `src/coverage.test.ts`; CHANGELOG'd as part of the `oneOf` entry.

Non-blocking follow-ups from Run 1 (all addressed pre-Run-2): two verified coverage
gaps (nested-in-`oneOf` honesty-walk test; `oneOf` strict-propagation test), the
`oneOf` warning leaking into `bun test`, the warning re-spamming wire-parsed
schemas (→ once-per-process), stale doc counts, and the README `~7.1 kB` row.

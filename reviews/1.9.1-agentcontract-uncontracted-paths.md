## Do before tagging (major + honesty fixes, doc-only)

### 1. (major, **confirmed**) The two agent-facing docs that SHIP still describe the pre-#10 surface

`CONTEXT.md:34` (mirrored byte-for-byte into `dist/context.md`) still reads *"Maps root path → schema into `{ check, describe }` … Strict validation by default — pass `{ strict: false }`"* — an **enumerated** options list that omits `unknownPath`, with zero hits for `affectedRoots` anywhere in either file. `llms.txt:32` still calls `agentContract` a *"fail-closed contract gate for agent write surfaces"*, which is false by default over uncontracted roots. `CONTEXT.md:35`'s "fail-closed invariants" bullet enumerates every protocol breach but not the one hole (`check()` returns bare `true` for "not my business").

Neither file is in `git diff v1.9.0...HEAD`; `dist/context.md` regenerated byte-identical, so the drift gate passes on stale prose. `llms.txt`'s only change is the version header, and that is stamped by `make-context.ts` — no human touched it, despite CLAUDE.md's "Update `CHANGELOG.md` and `llms.txt` with every release."

Not a regression (a consumer reading it behaves exactly as on 1.9.0), and README.md + CHANGELOG.md both document the new API correctly. But since the code change is **entirely opt-in, discoverability *is* the deliverable of 1.9.1** — and the audience `dist/context.md`/`llms.txt` exist for is precisely the LLM consumer who will never read the changelog.

**Fix:** add `affectedRoots(path)` and `unknownPath: 'allow' | 'refuse'` to the `agentContract` bullet in `CONTEXT.md`; add the "which `true` did you get" caveat to the fail-closed-invariants bullet; soften `llms.txt:32` to name the default (`fail-closed over contracted roots; uncontracted paths pass unless { unknownPath: 'refuse' }`). Re-run `bun run pack`, confirm `git status --porcelain` empty.

### 2. (minor, **confirmed**) CHANGELOG says "Additive, non-breaking"; `AgentContract` gained a **required** member

`src/contract.ts:52` adds non-optional `affectedRoots(path: string): string[]` to an interface exported via `index.ts` → `dist/src/contract.d.ts`. Reproduced with the repo's own pinned tsc: a consumer's `const fake: AgentContract = { check, describe }` fails with `TS2741` on `npm install` alone.

Impact is small and was over-stated by the original finding: tosijs declares its **own** `AgentContract` and consumes ours in the assignable direction (verified unaffected), and the type name appears in no README/CONTEXT/llms doc as an implementable seam. Do **not** weaken the member. Just make `CHANGELOG.md:10` honest — one line: *"Type-level change for implementers: if you implement or wrap `AgentContract`, add `affectedRoots(path) { return inner.affectedRoots(path) }` — don't stub `() => []`, that re-creates the #10 fail-open in your double."* This repo's README says the changelog, not the version letter, is the source of truth for what broke.

### 3. (minor, **confirmed in triage**) `unknownPath` is unvalidated and a typo fails OPEN

Reproduced: `agentContract({ 'app.billing': S }, { unknownPath: 'Refuse' })` constructs silently and `check('other', …)` returns `true`. The one option whose entire purpose is fail-**closed** posture degrades silently to fail-open on a capitalization slip or a value arriving from config/over the wire — while the same module *throws* on a schema keyword typo (`minumum`). A three-line construction guard plus a test is the cheapest honest fix; if it doesn't fit this tag, it goes to TODO.md (below) — but note it is a fail-open in security-adjacent code, which is the class this repo has narrowed three times.

## Follow-ups

### → this repo's `TODO.md` (correctness / security / efficiency / coverage / dx)

- [ ] **(security, confirmed)** `affectedRoots()`/`check()` miss bracket-**quoted** property access. `extendsPath` (`src/contract.ts:371`) is a raw prefix test, so with root `app.billing`, `app["billing"].rate` / `app['billing'].rate` / `app["billing"][0].x` all return `[]` and `check()` returns bare `true` — ungated — under the default `unknownPath: 'allow'`. Pre-existing in v1.9.0 and **not reachable in this stack** (tosijs's `by-path.ts` treats bracket contents literally and *throws* on that spelling, so the ungated spelling is also an inapplicable one), but 1.9.1's README/CHANGELOG/JSDoc now tell consumers to trust `affectedRoots` as *the* matcher "because hand-rolled versions miss bracket indexing" — and it is broken on the same axis. Fix: normalize `["k"]`/`['k']` → `.k` in `extendsPath`, or tokenize both sides into segments. Would be **major** for a consumer whose applier normalizes quoted brackets (lodash `_.set`) while leaving `unknownPath` at default — name that in the issue.
- [ ] **(security, confirmed)** Non-string `path` throws a raw `TypeError` instead of honoring the documented `true | Error` seam. `check(undefined, …)`, `check(null/0/{}/['app','order'], …)` and the newly-public `affectedRoots(undefined)` all throw `child.startsWith is not a function` (reproduced in triage), *including* under `{ unknownPath: 'refuse' }`. The internal-throw hardening at `contract.ts:443-449` wraps only `validate`, so the matcher runs outside it — and 1.5.0's CHANGELOG claims `check()` "never throws, as documented". Guard the entry: `typeof path !== 'string'` → return an `Error` naming the breach. Add a test beside the new #10 suite at `src/contract.test.ts:798+`.
- [ ] **(security, confirmed in triage)** `toPlain`'s duck-typed unwrap runs *before* the construction allowlist. Reproduced: `agentContract({ r: { type: 'object', properties: {}, additionalProperties: false, schema: true } })` constructs, `describe()` → `{"r": true}`, and `check('r', 1, { root: 'r', proposed: { anything: 'goes' } })` → `true` — a restrictive-looking schema silently becomes an **accept-all** gate. Reachable because the library markets accepting plain JSON schemas received over the wire, and `schema` (unlike `$schema`) is not a JSON Schema keyword so nothing else flags it. Narrow the unwrap to an actual builder (brand, or "`.schema` present and no other JSON-Schema-shaped key") so a stray `schema` key reaches `unenforced()` and is refused. Add a construction test asserting it throws.
- [ ] **(security/dx, from a refuted finding — the residual)** `agentContract` has no construction-time diagnostic for a root spelling its matcher can never traverse (`'/app/order'`, escaped dots), and the module does string matching on a `path` grammar it never defines. State the accepted grammar in the `affectedRoots` JSDoc + README (tosijs dot/bracket, unescaped; anything else reads as uncontracted and **fails open** unless `{ unknownPath: 'refuse' }`), and either reject or warn once on root keys outside it. Pin a JSON-Pointer-shaped path as `[]` in a test so the boundary is explicit rather than accidental.
- [ ] **(coverage)** The three new tests cover happy paths only. Add: `agentContract({}, { unknownPath: 'refuse' })` (verified: refuses the world — a gate with no schemas); an uncontracted path that *does* carry a proposal under `'refuse'`; the option-typo path; non-string path; quoted-bracket forms.
- [ ] **(dx / blast-radius, unverified)** `smoke.ts` — the new prepublish lane — never exercises this release's payload. Add two lines to the consumer fixture: `agentContract({x: S.schema}).affectedRoots('x[0].a').length === 1` and `agentContract({x: S.schema}, { unknownPath: 'refuse' }).check('other', 1) instanceof Error`. Make it habit that the fixture names whatever the release adds.
- [ ] **(dx, unverified)** `smoke.ts:26/42` derives the tarball name from `stdout + stderr` concatenated and takes `.pop()`. Clean here today (npm 11.18.0 writes 0 bytes to stderr), but any node deprecation/proxy/EBADENGINE line becomes the "filename" and the release gate dies with an opaque `renameSync ENOENT`. Split `out`/`err`, parse stdout only, and pack straight to the scratch dir (`--pack-destination`, which also kills the repo-root `.tgz` and the EXDEV risk of renaming across filesystems). Also preflight `npm` with a clear message, or use `bun pm pack`.

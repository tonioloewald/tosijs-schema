## Blockers

### B1 — `normalizePath`'s backtracking regex is quadratic on attacker-supplied paths; a long malformed path blocks the gate's event loop for tens of seconds
`src/contract.ts:471` · lenses: blast-radius + security + correctness · **verified**

```ts
p.replace(/\[(["']?)(.*?)\1\]/g, (_m, _q, key) => '.' + key).replace(/^\./, '')
```

With an empty quote group `\1` is empty, so at every unmatched `[` the lazy `.*?` expands to end-of-string looking for a `]` that never comes — O(n²) in path length. There is no length or shape screening before it; `check()` (`src/contract.ts:559`) only type-checks `typeof path`.

**Reproduced during triage** via `agentContract({'app.billing': …}).check('['.repeat(n), 1)`: 15ms at n=5k, 61ms at 10k, 244ms at 20k, **976ms at 40k** — clean quadratic scaling (4× length → 4× time), matching the reviewers' 2.9s at 65KB and 24.4s at 200KB. Every verdict is a correct `Error`, so the attacker is refused and pays nothing for the multi-second block.

Why blocker:
- **It is a regression this diff introduces.** `git show v1.9.0:src/contract.ts` has no regex at all — `affectedRoots` was a raw `startsWith`, O(n) (measured 0.04ms on the same 200KB payload).
- **It is on the least-trusted input in the subsystem.** `path` is the agent/client-supplied field on the documented capability gate, and `affectedRoots` is now public API pushed by the docs' `length === 0` posture, so it is directly exposed too.
- **Every consumer inherits it on a plain version bump**, with no code change on their side.
- **Nothing catches it**: `src/contract.test.ts` has no test exercising path length — the hostile-input tests cover shape only.

**Fix — and do not eyeball it.** The skeptic measured that the obvious one-character fix does *not* work: the greedy variant `/\[(["']?)([^\]]*)\1\]/g` still costs 629ms at n=30k, because greedy `[^\]]*` backtracks position-by-position for the same reason. What was measured to work: a non-backtracking alternation `/\[(?:"([^"]*)"|'([^']*)'|([^\][]*))\]/g` with `(a ?? b ?? c)` — 0.32ms on the 64KB payload (~9,000×). Belt-and-braces, add a cheap length/bracket-balance prefilter that refuses over-long paths up front with the existing `does not canonicalize` Error (fail-closed, matching this module's posture). Then add a regression test asserting a 200,000-char `'['.repeat(n)` path is refused in well under a second, and re-verify the new regex still canonicalizes every spelling pinned at `src/contract.test.ts:978-1001`.

## Majors — strongly recommended before tagging

These four are all **adversarially verified** and all live in `normalizePath`/`canBeJudged`, the same two functions as B1. Fixing them in the same pass is cheaper than four separate rounds — and this matcher has now been patched one spelling at a time across 1.8.0, 1.9.0, 1.9.1 and 1.10.0.

### M1 — Root keys are never checked for canonicalization, so a typo'd root constructs, is advertised by `describe()`, and gates nothing
`src/contract.ts:487` · correctness · verified

`canBeJudged` is applied to incoming paths (`:528`, `:559`) but never to `normedRoots` (`:487`). Reproduced: `agentContract({ 'app.list[0': S })` — a one-character typo — constructs, `describe()` advertises the root, and `check('app.list[0].rate', 999)` returns `true`. Completely ungated, forever. This is the exact failure the module's own M2 comment (`:488-495`) names — "a root that `describe()` advertises but that can never judge anything" — fixed for collisions and left open for canonicalization. It is also the class of thing this module refuses loudly elsewhere: a schema-keyword typo (`minumum`) throws at construction; a root-name typo silently disarms the gate. Not a regression (1.9.0 failed identically) and `{ unknownPath: 'refuse' }` closes it.

**Fix:** run the same judgeability test over root keys at construction. With both sides then guaranteed bracket-free, the `child.startsWith(parent + '[')` arm of `extendsPath` (`:434`) becomes dead — currently the only route by which a dead root matches anything at all — and should be dropped.

### M2 — Element-scoped roots (`movieObjs[id=666]`, `app.list[0]`) are bypassed by respelling the same element, and the new tests advertise that root shape as supported
`src/contract.ts:487` · security · verified

In tosijs's own `by-path` grammar an unquoted bracket body is an array **index** *or* an `[idPath=value]` element lookup — two spellings resolving to the same element but different strings. Reproduced: root `movieObjs[id=666]` gates `check('movieObjs[id=666].rate', 1)` but returns **`true`** for `check('movieObjs[1].rate', 1)` and `check('movieObjs.1.rate', 1)`; symmetrically root `app.list[0]` returns **`true`** for `check('app.list[id=abc].rate', 1)`. `src/contract.test.ts:993` explicitly contracts and endorses `'app.list[0]'` as a root shape. This falsifies the CHANGELOG's "No bracket spelling bypasses the gate any more". Blast radius is bounded: with a *container* root (`movieObjs`) all spellings are gated, so only bracket-element roots are exposed.

**Fix:** fail closed at construction — refuse a root whose canonical form contains an element-addressing segment (bare integer, or `k=v`), with an error saying "contract the containing array, not an element". Contracting the array is always coverable.

### M3 — A quoted key's interior dots fold into structural separators, so the one spelling that exists to carry dotted keys resolves to a different location than the applier writes
`src/contract.ts:471` · correctness · verified

`normalizePath` splices the captured key in without inspection, so `app["billing.rate"]` (one property named `billing.rate`) and `app.billing.rate` (three levels of nesting) canonicalize to the same string. The JSDoc at `:446` claims the fold "can only make MORE paths look CONTRACTED — the fail-closed direction"; that is false, because the extra segments attach the path to a root denoting a different location. Two reproductions both returning `true`, including one that **bypasses the brand-new `{ unknownPath: 'refuse' }` fail-closed posture by respelling**. The self-inconsistency is in the same function: the comment at `:452-457` names fully-bracketed segments as "what a defensive path builder emits to survive keys containing dots", and the fold destroys exactly that distinction. `README.md:496` ships the guarantee this breaks. There is also no escape hatch — contracting both locations throws "denote the same path".

Reachability caveat: tosijs's own `by-path.ts` cannot produce the dangerous write (it throws on `app["billing.rate"]` against an object), so exposure needs a lodash-style applier — which is precisely the compatibility target the code comment and README name.

**Fix (cheap, fail-closed, disturbs no existing test — no current test puts a dot inside a bracket):** have `canBeJudged` refuse a quoted bracket segment whose body contains `.`, `[` or `]`. Then narrow `README.md:496` and the `:463-466` comment so the shipped surface stops promising total bracket coverage.

### M4 — A `.` immediately before a bracket (`app.list.[0].rate`) reads as uncontracted, though lodash `_.set` — the applier the source itself names — resolves it into the contracted root
`src/contract.ts:483` · security · verified · *claimed severity minor; listed here because the fix site is shared with M1–M3*

The fold prepends a dot without absorbing one already present, yielding `app.list..0.rate`; `canBeJudged` does not treat `..` or a residual leading `.` as a canonicalization failure, so it falls through to `affected.length === 0 → true`. Measured `true` (ungated) for `app.list.[0].rate`, `app.["billing"].rate`, `app.['billing'].rate`, `app.[billing].rate`. Lodash 4's verbatim `stringToPath` parses these identically to their gated spellings — a measured gate/applier disagreement, not an appeal to convention. `app.billing.[0].rate` is also literally what the most common naive path builder emits. Same defect in the construction guard: `agentContract({ 'app.billing': S, 'app.["billing"].rate': N })` constructs, leaving a second dead-but-advertised root. Scope limit keeping this below M1–M3: tosijs's own `pathParts` resolves this spelling to a *different* location, so the in-house consumer is not exposed.

**Fix:** extend `canBeJudged` to refuse a normalized path containing `..` or a residual leading `.` (fail-closed, no grammar commitment), and add these spellings to the fail-open corpus test.
